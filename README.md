# 히오스 전략 코치

Heroes of the Storm 경기에서 전장과 밴픽, 양 팀의 전황을 입력하고 규칙 기반의 다음 행동 추천을 확인하는 정적 웹사이트 MVP입니다.

## 실행

- `index.html`을 브라우저에서 직접 열거나 저장소 루트에서 `python3 -m http.server 8000`을 실행한 뒤 `http://localhost:8000`에 접속하세요.
- 입력 내용은 브라우저의 `localStorage`에 저장되며, 같은 브라우저와 기기에서 다시 열면 이어서 사용할 수 있습니다.

## 현재 범위

- 첫 화면에서 전장과 양 팀 밴·픽을 입력하는 게임 준비 화면
- 페이지 최상단에 영어·한국어 응원 문구 12개 중 하나를 표시하고, 같은 문구를 연속으로 반복하지 않으며 60초마다 변경
- 전장을 선택하면 해당 전장에 대응하는 로컬 WebP 이미지가 페이지 배경에 표시되며, 선택 내용과 함께 자동 저장 (죽음의 광산 포함)
- 선택한 전장의 목표·라인 구조를 바탕으로 추천 영웅과 우선순위를 낮춰 고려할 영웅 안내
- 검색 가능한 영웅 선택, 잘아타스 포함, 밴·픽 간 중복 선택 방지
- 준비 화면에서 새 경기를 시작하거나 저장된 경기를 이어할 수 있으며, 새 경기 시작 시 전장·밴픽을 유지하고 이전 전황만 초기화
- 밴픽 픽을 전황 입력의 영웅 칸에 자동 반영
- 게임 중 화면에서 게임 시각·다음 오브젝트, 오브젝트 경합, 양 팀 사망 수를 빠르게 입력하고, 세부 전황은 접어서 필요할 때만 표시
- 아군 사망 빠른 버튼은 영웅별 생존 입력을 열어 정확한 영웅의 사망 상태를 선택하도록 안내
- 양 팀 5명의 생존/사망, 부활 시간 카운트다운과 0초 도달 시 자동 생존 처리, 주요 궁극기 상태 입력
- 양 팀 현재 레벨 차이와 1·4·7·10·13·16·20 특성 구간, 생존 인원, 부활 시간, 오브젝트까지 남은 시간을 반영한 일반 규칙 기반 추천
- 오브젝트 시점에 부활 시간을 기준으로 양 팀의 예상 합류 인원을 계산하며, 부활 시간이 비어 있으면 확정 인원과 추정 범위로 표시
- 밴픽/영웅이 미확인인 슬롯은 확정 생존 수에서 제외하고 가능한 인원 범위로만 계산해, 미선택 슬롯의 기본 생존 상태가 수적 우위·열세를 만들지 않도록 처리
- 확인된 양 팀 사망 인원 차이와 오브젝트 상황을 바탕으로 킬 이후 오브젝트·캠프·라인/구조물 압박 우선순위를 안내
- 가까운 용병 캠프 점령 가능 여부와 안전한 반대 라인 웨이브/구조물 교환 가능 여부를 입력해 불리한 오브젝트 경합의 대안을 추천
- 최근 한타 결과(승리·패배·큰 피해 없는 교전)를 선택해 킬 이후 행동 판단에 반영
- 오브젝트까지 남은 시간과 한타 결과를 함께 고려해 임박한 목표 합류와 시간이 남은 캠프·라인 교환을 구분
- 맵별 첫 오브젝트 시각과 후속 규칙(게임 시계 기준 / 이전 이벤트 종료 기준 / 시간 범위 / 수동 보정)을 데이터로 분리
- 저주받은 골짜기(공물·저주), 파멸의 탑(종탑 보유), 용의 둥지(상·하단 신단) 상태를 빠른 입력으로 기록해 맵 고유 전략 추천에 반영
- 맵별 사실 데이터와 상태 정규화·전략 평가 코드를 `map-strategies.js`로 분리하고, 공통 생존 위험 분석 뒤에 맵별 승리 조건을 연결
- 맵별 추천에 실행·중단 조건, 대안 행동, 예상 이득과 위험을 명시하고, 필요한 맵 상태가 미입력되면 해당 규칙을 추정하지 않음
- 게임 중 전황 화면에서 게임 시작을 눌러 작동하는 경기 시계, 게임 종료·일시정지·재개·±30초 보정 및 초 단위 직접 수정
- 오브젝트 시작·종료와 상황을 빠른 입력으로 기록하고, 확보 팀 선택과 시계 보정·이전 종료 시각 수정·이벤트 되돌리기는 고급 설정에서 조작
- 오브젝트까지 90초 이상 / 60–90초 / 30–60초 / 30초 이내 구간에 따라 라인·캠프 준비와 합류 추천을 변경
- 영웅별 생존·궁극기나 레벨 입력 없이도 맵 규칙과 게임 시계로 기본 추천을 제공하며, 타이머가 확인되지 않는 맵은 안전한 라인 경험치를 기본으로 안내
- 캠프는 등장 시각만으로 추천하지 않고, 게임 내 가용성·안전과 오브젝트 합류 시간을 확인하도록 안내
- 즉시 생존 위험, 예상 합류 인원, 오브젝트 상태, 한타 결과, 레벨·특성, 궁극기 참고 순으로 우선순위를 적용한 추천
- 추천 카드 기본 화면에는 최우선 행동, 핵심 근거와 주의 사항을 표시하고 실행 조건·대안·전황 요약은 접어서 확인
- 일부 영웅의 궁극기 교전 영향 잠재력을 보조 판단에 사용하며, 선택 궁극기·실제 재사용 대기시간·미등록 영웅의 영향은 확정하지 않음
- 초반 경험치 수급, 특성 구간 우위, 후반 오브젝트 위험을 시점에 따라 다르게 안내
- 추천 행동과 양 팀 생존 인원 우열을 색상으로 강조해 표시
- 게임 중 추천에 상황 진단, 우선순위·분야 배지, 판단 근거와 입력 정보 충실도 표시
- 추천은 입력된 전황에 대한 규칙 기반 참고이며, 승률이나 실제 경기 데이터를 근거로 하지 않음

맵별/영웅별 조합 분석이나 승률 데이터, 게임 클라이언트 연동, AI API는 포함하지 않습니다. 맵 전략 모듈은 우선 저주받은 골짜기·파멸의 탑·용의 둥지에 한정됩니다. 공물 누적, 종탑 수, 신단 소유는 사용자가 입력해야 하며 미확인 상태를 추정하지 않습니다. 한타 결과는 사용자가 입력한 값이 우선이며, 입력하지 않은 경우에만 확인된 사망 인원 차이를 제한적인 추정으로 사용합니다. 오브젝트 구간(90/60/30초)은 초기 운영 기준이며 맵 규칙을 대체하지 않습니다. 시간 범위가 있는 반복 목표는 빠른 시점 기준으로 합류 준비를 권하지만 정확한 활성 시각으로 취급하지 않습니다. 위치·부활 후 이동 시간은 예상 합류 인원에 반영되지 않습니다. 지도 데이터에서 고정 시각이나 반복 규칙을 확인할 수 없는 목표는 자동으로 시간을 만들어내지 않고 수동 입력을 요구합니다. 캠프 등장 시각은 현재 데이터에 포함되지 않으므로 캠프 타이머만으로 점령을 권하지 않으며, 게임 내 가용성·안전과 합류 시간을 따로 확인해야 합니다. 맵과 게임 시계만으로 기본 라인·합류 준비 추천을 제공하지만, 타이머만으로 적 위치·오브젝트 진행 상태·승패를 추정하지 않습니다. 시계는 로컬 시간으로 진행하며, 실제 게임과 어긋날 수 있으므로 일시정지·±30초 버튼·시각 입력으로 보정할 수 있습니다. 게임 클라이언트와 자동 동기화하지 않습니다. 캠프와 라인 교환 추천은 사용자가 입력한 안전 여부에 의존하며 실제 시야·상대 위치를 판별하지 않습니다. 레벨·특성 안내는 입력된 양 팀 레벨과 일반적인 특성 구간에 따른 규칙 기반 참고이며 레벨 열세만으로 오브젝트 포기를 단정하지 않습니다. 궁극기 영향도는 일부 영웅에 대한 대략적인 교전 기여 추정이며 선택한 궁극기 자체를 식별하지 않습니다. 기존 저장 데이터는 계속 불러올 수 있고, 예전 버전의 기본 부활 시간 0초는 입력되지 않은 값으로 처리합니다. 알 수 없는 전황은 승리 조건처럼 단정하지 않고 추가로 필요한 정보를 표시합니다.

맵 오브젝트 시간은 [저주받은 골짜기](https://heroesofthestorm.fandom.com/wiki/Cursed_Hollow), [공포의 정원](https://heroesofthestorm.fandom.com/wiki/Garden_of_Terror), [파멸의 탑](https://heroesofthestorm.fandom.com/wiki/Towers_of_Doom), [불지옥 신단](https://heroesofthestorm.fandom.com/wiki/Infernal_Shrines), [브락시스 항전](https://heroesofthestorm.fandom.com/wiki/Braxis_Holdout), [볼스카야 공장](https://heroesofthestorm.fandom.com/wiki/Volskaya_Foundry), [용의 둥지](https://heroesofthestorm.fandom.com/wiki/Dragon_Shire), [영원의 전쟁터](https://heroesofthestorm.fandom.com/wiki/Battlefield_of_Eternity), [하늘 사원](https://heroesofthestorm.fandom.com/wiki/Sky_Temple), [핵탄두 격전지](https://heroesofthestorm.fandom.com/wiki/Warhead_Junction), [알터랙 고개](https://heroesofthestorm.fandom.com/wiki/Alterac_Pass), [하나무라 사원](https://heroesofthestorm.fandom.com/wiki/Hanamura_Temple), [거미 여왕의 무덤](https://heroesofthestorm.fandom.com/wiki/Tomb_of_the_Spider_Queen), [블랙하트 항만](https://heroesofthestorm.fandom.com/wiki/Blackheart%27s_Bay), [죽음의 광산](https://heroesofthestorm.fandom.com/wiki/Haunted_Mines)의 커뮤니티 위키 설명을 참고했습니다. 게임 업데이트에 따른 규칙 차이가 있을 수 있으므로, 실제 경기의 표시가 다르면 수동으로 보정해야 합니다.

전장 배경 이미지는 저장소의 `images/` 폴더에서 불러옵니다. 죽음의 광산은 첫 광산 3:00, 양 팀 골렘 처치 후 2:00 재개방 규칙을 사용합니다. 후속 타이머 정확도를 위해 두 골렘이 모두 처치된 시점에 오브젝트 종료를 입력하세요.
게임 중 영웅 초상화도 외부 이미지 CDN에서 불러옵니다. 생존/사망은 두 버튼으로 바로 전환할 수 있습니다.

## 배포

`master` 브랜치에 변경 사항을 push하면 GitHub Actions가 `index.html`과 `map-strategies.js`를 GitHub Pages에 배포합니다. 저장소 설정에서 Pages의 배포 소스가 GitHub Actions로 지정되어 있어야 합니다.

## 맵 전략 테스트

Node.js 내장 테스트 러너로 맵별 판단과 추천 연결을 확인합니다.

```sh
node --test tests/map-strategies.test.js
```
